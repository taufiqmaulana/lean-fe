# Lean FE

A lean, opinionated frontend base for admin-style apps: a collapsible multilevel sidebar, light/dark/system theming, login with protected routes, a `Page` layout component and a server-driven, virtualized `DataTable`.

## Stack

| Concern | Tool |
| --- | --- |
| UI | React 19, TypeScript 7 |
| Build | Vite 8 |
| Styling | Tailwind CSS v4 (CSS-first, no config file) |
| Components | shadcn/ui (Base UI primitives, Nova preset), lucide icons |
| Routing | TanStack Router (file-based, type-safe) |
| Server state | TanStack Query |
| Tables | TanStack Table v9 + TanStack Virtual |
| Devtools | TanStack Devtools (Router, Query and a custom Data Tables panel) |
| Lint & format | Biome |
| Package manager | pnpm |

## Getting started

Requirements: Node.js 24+ and pnpm 10 (`corepack enable` picks the version from `package.json`).

```sh
pnpm install
pnpm dev
```

Open the URL Vite prints and sign in with the demo account: **demo.user@example.com / password**.

| Script | What it does |
| --- | --- |
| `pnpm dev` | Dev server with HMR and devtools |
| `pnpm build` | Production build to `dist/`, then type-check |
| `pnpm preview` | Serve the production build locally |
| `pnpm check` | Lint, format and sort imports and Tailwind classes (writes fixes) |

Run `pnpm check` and `pnpm build` before committing.

### Environment variables

| Variable | Used by | Default |
| --- | --- | --- |
| `VITE_API_URL` | `src/lib/api.ts`, base URL for API requests | `''` (same origin) |

Vite inlines `VITE_*` variables at build time, so each environment needs its own build. Put local values in `.env.local`, which git ignores.

### Where things go

- **`src/routes`** holds route files only, named after their URL. A page component used by one route stays in that route file until a second place needs it.
- **`src/ui`** holds every reusable React component, kept flat (no subfolders). shadcn primitives and app components sit side by side; app components are named after their role (`app-*`, `nav-*`, `data-table*`).
- **`src/lib`** holds everything that is not a component: setup, stores, API clients, config and hooks.
- **Nothing new at the project root.** It is reserved for tool configs that must live there.

### Routing conventions

- Routes are generated from files: `src/routes/_app/users.tsx` serves `/users`.
- A leading `_` makes a **pathless layout**: `_app.tsx` wraps its children without adding to the URL. Everything under `_app/` requires a session.
- Public pages (such as `login.tsx`) sit directly in `src/routes/`.
- Route context provides `queryClient` and `auth`; use them in `beforeLoad` and `loader`.

## Code style

Biome enforces formatting and lint rules. Run `pnpm check` to apply them; there is no ESLint or Prettier.

### Formatting (automatic)

- 2-space indentation, 100-character lines
- Single quotes, no semicolons
- Imports are sorted automatically; Tailwind classes are sorted by `useTailwindSortedClasses`
- LF line endings (set `git config core.autocrlf false` on Windows)

### TypeScript

- `strict` mode, plus `noUnusedLocals` and `noUnusedParameters`.
- Use `import type` for type-only imports (`verbatimModuleSyntax` is on).
- Import from `src` with the `@/` alias: `@/ui/button`, `@/lib/auth`. Don't use long relative paths.
- **Named exports only.** The one exception is the `Route` export that the router requires in route files.
- Avoid `any`. Where it's unavoidable, add a `biome-ignore` comment that explains why.

### Naming

| Thing | Convention | Example |
| --- | --- | --- |
| Files and folders | kebab-case | `app-sidebar.tsx`, `table-events.ts` |
| Components | PascalCase | `AppSidebar`, `DataTable` |
| Hooks | `use` + camelCase | `useAuth`, `useTheme` |
| Types | PascalCase, no `I` prefix | `MenuItem`, `DataTableQuery` |
| Constants and singletons | camelCase | `queryClient`, `auth`, `menu` |

### Components and styling

Follow the shadcn/ui rules:

- **Use semantic color tokens**, not raw colors: `bg-background`, `text-muted-foreground`, `border-border`. Don't write `bg-gray-900` or manual `dark:` color overrides; tokens switch with the theme automatically.
- **Use `className` for layout** (spacing, sizing, position), not to restyle a component's colors or typography. Use variants instead (`variant="outline"`, `size="sm"`).
- **Use `flex` or `grid` with `gap-*` for spacing**, never `space-x-*` or `space-y-*`.
- **Use `size-*`** when width equals height, and `truncate` for single-line overflow.
- **Use `cn()`** for conditional classes, not string templates.
- **Mark icons inside buttons** with `data-icon="inline-start"` or `"inline-end"`, and don't size them yourself.
- **Use existing components** before writing custom markup: `Empty` for empty states, `Alert` for messages, `Skeleton` for loading, `Badge` for labels, `Separator` for dividers.
- **Build forms with `FieldGroup` and `Field`.** Mark errors with `data-invalid` on the `Field` and `aria-invalid` on the input.
- **Base UI composition:** to render a component as another element, use the `render` prop (`render={<Link to="/" />}`), not `asChild`.

### Data and state

- **TanStack Query owns server data.** Don't copy query results into `useState`.
- **Put everything that changes a request in the query key** (filters, sorting, page size).
- **Keep TanStack Table `columns` at module scope** (or memoized) so they stay stable between renders.
- **Use component state for UI only**, and module-level stores (like `auth`) for app-wide client state.

### Comments

Explain *why*, not *what*: constraints, workarounds and non-obvious decisions. Code that is self-explanatory needs no comment.

## How to

### Add a page

1. Create `src/routes/_app/<path>.tsx`. The dev server generates the route automatically.

   ```tsx
   import { createFileRoute } from '@tanstack/react-router'
   import { Button } from '@/ui/button'
   import { Page } from '@/ui/page'

   export const Route = createFileRoute('/_app/orders')({ component: Orders })

   function Orders() {
     return (
       <Page title="Orders" description="All customer orders." toolbar={<Button>New order</Button>}>
         …
       </Page>
     )
   }
   ```

2. Add it to `menu` in `src/lib/app.ts` so it shows in the sidebar. Items nest to any depth with `items`; the active item and its parents highlight automatically.

### Add a server-driven table

Define columns at module scope with `createColumns`, and pass a `fetchPage` function that returns `{ rows, nextCursor, total }`:

```tsx
const col = createColumns<Order>()
const columns = col.columns([
  col.accessor('number', { header: 'Order', meta: { filter: { type: 'text' } } }),
  col.accessor('status', {
    header: 'Status',
    meta: { filter: { type: 'select', options: [{ label: 'Paid', value: 'paid' }] } },
  }),
])

<DataTable
  columns={columns}
  queryKey={['orders']}
  fetchPage={({ cursor, pageSize, filters, sorting, signal }) =>
    api(`/orders?${new URLSearchParams({ … })}`, { signal })
  }
  getRowId={(order) => order.id}
  toolbar={({ filters, total }) => <Button size="sm">Export {total}</Button>}
/>
```

Filtering and sorting happen on the server. The table virtualizes rows and loads the next page as you scroll.

### Add a shadcn component

```sh
pnpm dlx shadcn@latest add dialog
pnpm check
```

Components land in `src/ui`. Run `pnpm check` afterwards to apply the project's formatting. If a generated file breaks a lint rule, turn that rule off for that file only in the `overrides` section of `biome.json`; don't edit the generated code.

### Connect a real backend

- **Login:** in `src/lib/auth.ts`, replace `mockLogin` in `auth.login` with a call to your endpoint that returns `{ token, user }`.
- **Data:** call `api()` from `src/lib/api.ts`. It adds `Authorization: Bearer <token>` and ends the session on a 401.
- **Set `VITE_API_URL`** for each environment.
- **Delete `src/lib/demo.ts`** once nothing imports it.

The route guard only hides pages from signed-out users; the API must still check the token on every request.

### Add a devtools panel

Define typed events with an `EventClient` (see `src/lib/table-events.ts`), emit them from app code, build a panel component (see `src/ui/data-table-devtools.tsx`), and register it in the `plugins` list in `src/lib/main.tsx`.

## Devtools

In development, press **Ctrl+~** (or click the floating button) to open TanStack Devtools, with tabs for Router, Query and Data Tables.

- **Go to source:** hold **Shift+Alt+Ctrl** (or **Cmd** on macOS) and click an element to open its file in your editor.
- **Console piping:** browser logs appear in the terminal as `[Client] …`.

The devtools, their panels and the source annotations are removed from production builds automatically.

## Deployment

The `deploy/` folder builds a static image served by nginx, with a fallback to `index.html` so client-side routes work on refresh, plus long-term caching for hashed assets:

```sh
docker build -f deploy/Dockerfile --build-arg VITE_API_URL=https://api.example.com -t lean-fe .
docker run -p 8080:80 lean-fe
```
